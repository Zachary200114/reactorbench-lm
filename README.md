# ReactorBench-LM

ReactorBench-LM is a research project for building and evaluating a small decoder-only Transformer, initialized and trained from scratch, on event narratives generated by Aster Station: a wholly fictional causal environment.

> All systems, events, values, policies, and narratives in ReactorBench-LM are synthetic and fictional. No real plant records, operating procedures, event reports, Navy material, restricted information, or proprietary manuals were used. The model is an educational language-model experiment and is not suitable for operational, engineering, licensing, emergency, maintenance, security, or safety decisions.

## Research question

Can a small causal Transformer trained entirely from random initialization learn the temporal structure of a disclosed synthetic event world and generalize to held-out wording, component roles, and fault combinations better than preregistered simple baselines?

The project is intended to demonstrate the complete path from an invented causal state machine to a trained and evaluated language model:

```text
latent Aster state
    -> bounded observation channels
    -> canonical events
    -> project-authored narrative renderer
    -> leakage-resistant dataset splits
    -> project-trained tokenizer
    -> baselines and from-scratch Transformer
    -> behavioral, robustness, and compositional evaluation
    -> narrow inference API and Research Editorial interface
```

Ground truth belongs to the structured generator, never to rendered prose or model output.
Developmental dataset contracts are snapshot-reviewed, not frozen as version 1.

## Non-negotiable boundaries

- All scenarios and training narratives are project-authored and synthetic.
- Real plant logs, reports, procedures, manuals, setpoints, facility data, and Navy nuclear information are excluded.
- Values are normalized or use explicitly fictional synthetic units.
- The core model receives no pretrained weights and uses no hosted LLM for corpus generation, labeling, primary judging, or behavior.
- Outputs are measured fictional labels, not real operating guidance.
- The project is a benchmark and research demonstration, not an operator assistant, engineering model, digital twin, safety system, or control-room replica.
- Arbitrary files, URLs, model paths, checkpoints, and real-world logs are outside the interface contract.

See [the canonical project requirements](research/PROJECT_REQUIREMENTS.md) for the complete scope and explicit non-goals.

## Development baseline

- Python 3.12 is the project baseline; the declared compatibility window is Python 3.12 through 3.13.
- `uv` manages the environment and locked dependency workflow.
- Pydantic v2 defines strict runtime data contracts.
- PyTorch is permitted later for tensors, automatic differentiation, optimization, and Apple MPS acceleration. It is not part of the initial schema foundation.

The foundation workflow is:

```bash
make sync
make check
make build
```

`make sync` installs all declared dependency groups from the present local
lockfile. Other quality commands also run against the locked environment. The
dated checkpoint above records successful local verification; exact evolving
command outcomes belong in [the implementation status](docs/IMPLEMENTATION_STATUS.md).
The lockfile and reviewed schema snapshots are preserved in local Git, but no remote
repository exists.
